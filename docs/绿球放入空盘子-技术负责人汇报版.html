02 / 系统架构

系统架构与责任边界

任务树负责控制流，世界快照负责现实事实，规划工件负责几何方案，动作网关负责物理副作用。 四类状态分开管理，才能定位“任务失败、规划失败、执行失败、验证失败”分别发生在哪里。

主执行链

从自然语言目标到单次物理动作
任务输入 明确目标对象、目标容器、前置条件与完成条件。
→
任务规范化 把自然语言整理为可验证的任务程序。
→
任务树内核 维护执行栈、节点状态、递归子任务与返回位置。
→
条件与规划 读取快照，选择对象，生成导航、抓取和搬运方案。
→
动作安全网关 检查计划新鲜度、资源、前置条件，只放行一次动作。
→
机器人与现场 移动、抓取、释放，并产生新的观察证据。
观察与验证闭环
观察归一化 合并视觉、夹爪、底盘与安全状态。
→
世界快照 形成不可变、带版本号的现实事实集合。
→
独立验证 只依据最新快照判断完成、重试或重新规划。
递归修复闭环
结构化诊断 记录哪个条件失败、证据来自哪一版世界。
→
修复提案 生成受约束的临时子任务，不直接修改现实。
→
挂载并返回 子任务成功后回到原失败节点继续执行。
任务树唯一写入者 只有任务树内核可以改变节点状态、挂载修复子树和推进执行栈。
现实事实唯一来源 只有新观察可以生成新世界快照；规划结果不能宣称物体已经移动。
物理动作唯一入口 规划器和修复器不能直接控制机器人，所有动作必须经过安全网关。
03 / 世界快照

世界快照如何规范化构建

世界快照不是画面截图，也不是规划结论的集合。 它是同一时刻、同一坐标体系下，经过身份合并、冲突消解和证据标记后冻结的一版事实数据。

输入来源
物体观察 类别、颜色、形状、位置和可见性
空间关系 在地面、桌面、盘内或被夹持
机器人状态 底盘位姿、关节、夹爪占用状态
固定环境 桌子、挡板、边界和可通行区域
安全与时间 碰撞、急停、时间戳和来源可信度
步骤 1
时间对齐 只合并时间窗口一致的观察，避免旧画面与新机器人状态混用。
→
步骤 2
身份合并 依据属性、位置连续性和历史标识，把多次观察归到同一实体。
→
步骤 3
坐标与单位统一 转换到统一世界坐标，统一长度、角度、朝向和几何表达。
→
步骤 4
关系与冲突处理 推导确定的支撑或包含关系；矛盾项按新鲜度和证据质量处理。
→
步骤 5
冻结版本 形成不可变快照，记录版本号、来源和可信状态，供后续模块读取。

下游模块负责的判断

条件检查 由“红球在盘内”推出“盘子当前不空”。
路线规划 判断某个接近位、某条路径是否与黄箱冲突。

04 / 递归任务

任务递归与实际分支

“盘子不空”是合法的递归修复条件；“搬黄箱”则来自一次不完整的路线判断。 两者都表现为临时子任务，但证据强度不同。

主任务 把绿球放入空盘子
开始条件 目标盘子为空；绿球可定位、可抓取；机器人安全状态正常。
完成条件 绿球位于盘内；夹爪为空；结果由最新世界快照确认。
本次实际执行树

候选失败被升级为环境改造

主任务：绿球入盘 盘子不空，暂停主任务。
临时任务：将红球移出盘子 该修复有直接世界事实支持。
第二层任务：搬走黄箱 两个正面候选失败后插入，未比较桌侧绕行。
返回红球任务，再返回绿球任务 最终成功，但经历了额外环境变化。
完整规划应形成的执行树

保留必要修复，删除不必要分支

主任务：绿球入盘 盘子不空，暂停主任务。
临时任务：将红球移出盘子 继续生成桌前、左右侧和桌后接近位。
执行方案：从右侧绕到桌后 底盘路线与机械臂抓取均通过，无需搬箱。
返回绿球任务 基于红球移走后的新快照重新规划。
05 / 故障链

错误决策链发生在哪里

两条链使用同一张障碍地图。差异不在避障算法，而在路径规划器收到的候选接近位是否完整。

实际链路 从局部候选失败到搬箱
1
建立障碍地图 桌子、固定挡板和黄箱均进入碰撞模型。
2
生成接近位 经过保守边界与机械臂距离筛选后，只剩两个正面位置。
3
正面位置碰撞 两个位置均与黄箱的底盘安全距离冲突。
4
错误升级诊断 “已生成候选均失败”被等同为“路线被黄箱阻断”。
5
挂载搬箱子任务 系统改变环境后重新计算正面路线。
应有链路 从候选覆盖到方案比较
1
建立同一障碍地图 黄箱仍然是障碍物，不需要从模型中忽略。
2
覆盖目标四周 桌前、左侧、右侧、桌后分别生成接近位和拒绝原因。
3
逐候选检查底盘路线 桌后偏右接近位可由桌子右侧绕行到达。
4
检查停靠与抓取 停靠无碰撞，机械臂可到达红球。
5
比较方案代价 绕行不改动环境，应优先于额外搬运黄箱。
关键判断： 路径规划器没有拒绝桌侧路线，它从未收到这个接近位。 因此本问题属于候选生成与修复触发条件缺陷，不属于 A* 或碰撞检测失效。

07 / 根因定位

根因定位与影响

直接原因是几何筛选过保守；系统性原因是候选生成没有覆盖契约， 修复触发也没有要求“全方向已检查”的证据。

现象
系统搬走黄箱 任务最终成功，但选择了改变环境的分支。
→
直接原因
仅保留正面候选 桌侧与桌后接近位未进入路径比较。
→
代码原因
桌体外扩区域过大 桌子四周额外外扩 0.25 m，使合法站位在路径搜索前被排除。
→
架构原因
缺少候选完备性证明 “全部已生成候选失败”可以直接触发搬障碍物修复。
工程定位
D:\GeminiER2Harness\er2sim\control.py
桌体保守包络：第 848 至 854 行；接近位生成与筛选：第 1195 至 1279 行。
本场景计算出的外扩区域约为 (-0.25, 1.45, -0.48, 0.57)。
任务结果 最终成功，说明递归修复和返回机制可用。
执行效率 增加一次黄箱搬运，并引发后续路线重新计算。
物理风险 多一次抓取、搬运和放置，就多一次碰撞或放置失败机会。
可扩展性风险 场景更拥挤时，同类漏检会频繁触发不必要的环境改造。
08 / 整改方案

整改方案与验收标准

修复重点不是简单增加一个“右侧特例”，而是建立候选覆盖、拒绝证据和方案比较三项通用能力。

优先级
整改项
实现要求
验收证据
P0
候选覆盖契约
按桌前、左侧、右侧、桌后或自由空间扇区生成接近位；每个方向必须记录候选或明确拒绝原因。
日志可回答“哪些方向生成了多少候选、在哪一层被过滤、依据是什么”。
P0
修复触发门槛
触发搬障碍物前，必须证明所有有效方向均无可行底盘路线或机械臂抓取方案。
“候选为空”与“全空间不可达”使用不同诊断码，不允许直接互换。
P0
当前场景回归测试
固定黄箱、桌子、挡板、红球和机器人初始状态，验证右侧绕行被选中。
任务树中不得出现“搬黄箱”修复子树；底盘和抓取检查全部通过。
P1
分离几何安全裕量
底盘避碰、机械臂可达和桌体保护分别建模，避免用同一个 0.25 m 包络承担全部约束。
改变任一裕量时，可独立观察候选数量、碰撞结果和抓取可达性。
P1
方案代价比较
同时计算绕行距离、动作数量、环境改动、失败风险和计划失效范围。
存在安全绕行时，环境改造方案必须有明确的更优证据才能胜出。
P1
规划可观测性
输出生成前、几何过滤后、路线检查后、抓取检查后的候选计数和拒绝原因。
单次复盘可定位到候选生成、碰撞检查、路径搜索或机械臂检查中的具体阶段。
发布验收条件
场景回归 黄箱保持原位，系统自动选择右侧绕行并完成红球抓取。
安全不降级 黄箱继续参与障碍检测，桌后停靠位与机械臂路径均无碰撞。
诊断可解释 每个方向的候选、过滤阶段和拒绝依据均可从运行记录还原。
修复触发正确 只有所有绕行方案均失败时，才允许生成搬障碍物子任务。
快照依赖正确 物体位置变化后旧规划失效，并基于新世界版本重新生成。
反例覆盖 人为封闭桌侧路线时，系统能够给出全方向不可达证据并合理搬箱。

最终判断

本次不是“规划时没有考虑黄箱”，而是“考虑了黄箱，但没有完整考虑接近红球的方向”。 系统具备递归修复能力，但修复触发条件需要增加规划完备性约束。
